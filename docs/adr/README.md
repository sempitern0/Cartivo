# Registro de decisiones

Todos los ADRs empiezan como propuestas. La existencia del documento no acredita implementación ni elimina un bloqueo de licencia.

| ADR | Tema | Estado |
|---|---|---|
| [001](001-platform-and-scope.md) | Catálogo, stack y distribución | Propuesto |

| [007](007-nes-experimental-js.md) | NES NROM experimental en Worker; SRAM transaccional | Aceptado para incremento experimental; WASM y release pendientes |

Para aceptar un ADR registrar fecha, decisión del responsable, alternativas descartadas y evidencia. Cuando haya código, enlazar commit/build y pruebas pertinentes. Cambiar una decisión relevante requiere un ADR sucesor o una revisión explícita, no una desviación oculta en implementación.
